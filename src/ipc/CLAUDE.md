# Remote control (IPC)

Every GUI instance serves a JSON-lines protocol on `$XDG_RUNTIME_DIR/sketerm/<pid>.sock` (a `GSocketService`, so everything runs on the main loop). `sketerm cli <command>` is the client: `list`, `send-text`, `send-keys`, `get-text`, `screen-info`, `new-tab`, `split`, `focus`, `close-pane`, `set-title`, `set-tab-color`, `new-durable-tab`, `attach-session`. Child processes inherit `SKETERM_SOCKET` and `SKETERM_PANE_ID`, so `--pane self` works from inside any pane. Code in `src/ipc/` (`protocol.zig`, `server.zig`, `client.zig`, `mux_cli.zig`, `keys.zig` = pure chord→bytes encoder for send-keys). Socket discovery in `resolveSocket` must skip `mux.sock`.

`sketerm mcp` (`src/ipc/mcp.zig`) is a Model Context Protocol server on stdio for AI assistants: JSON-RPC 2.0 NDJSON in/out, tools adapted onto the same socket. Terminal tools (list_terminals, read_screen, screenshot_pane, send_text, send_keys, run_command, wait_idle, new_tab, split_pane, focus_pane, close_pane) go through the GUI socket. **Headless GUI-app tools** (`appTool` in mcp.zig, backed by `src/ipc/appdrive.zig` — a proto-v5 mux client with per-channel replica compositors, GTK-free) talk to the mux daemon DIRECTLY, so they work with no GUI: launch_app (cwd/env/wait_for; `size:"WxH"` = the virtual output mode via SpawnReq.output_width/height, confirmed back in the spawn ok and WARNED about when an older daemon ignored it; replies with the first window's screenshot inline, captured after a `stable_ms` settle — default 500ms — so it lands past the blank pre-paint frame, with a caption note when still mid-paint or first-frame + the daemon-host child pid — a gdb handle; argv-array commands exec directly so the pid IS the app; `debug:"gdb"|"valgrind"` runs under a wrapper whose crash backtrace/report lands in app_log; `gdb_commands:[...]` = extra gdb `-ex` commands run AT THE CRASH POINT after the automatic bt full + info registers — dump the exact state you'd otherwise relaunch for; client-side only, the wrapper argv rides SpawnReq.argv), get_app_state, screenshot_app (bounded/downscaled inline PNG; region crop + integer zoom; wait_change, `stable_ms` settle-then-capture, `stats_only` cheap diff probe without an image, `burst`=N multi-frame capture gated on `min_change_pct`), app_output (the app's PTY stdout/stderr — appdrive keeps a termdrive-style Screen mirror; app_log is the documented source of truth for line output: exit summaries serve `recent_output` from the pre-exit log-ring stash — unwrapped full lines — with the grid tail only as fallback; exit decode is complete: -signo → signaled/signal_name + `crashed`, shell-wrapped 128+N → `likely_signal`, sanitizer output in the log → `sanitizer_report`, a gdb wrapper's "Program received signal" → `debugger_caught_signal`), app_log (daemon-side indexed log ring per session, `src/mux/logring.zig`: escape-free lines with stable increasing ids, bounded 1000 lines/2MB drop-oldest; tail view truncates at 300 chars, any id re-readable in full; the final log is pushed ahead of `.exit` so post-mortems survive teardown; **`OSC 5522;label` from the app = a labelled marker line + a client-stashed screenshot of the window at that instant**, `OSC 5522;+N;label` = the Nth FUTURE commit instead (exit resolves stragglers — ids never dangle), both fetched via the line id; markers are token-bucket rate-limited (burst 8, 2/s — a cat'ed escape-laden file can't evict real lines or flood viewers with encodes; excess counted in the app_log header) — wire frames log_get/log_data/marker, append-only; a log reply delayed behind heavy frame streaming is refetched over a FRESH side connection (`appdrive.logGetFresh`: proto-1 hello so no native-channel replay, empty daemon-side queue so log_data lands right after the attach snapshot — the primary connection's queue grows without bound between tool calls on a continuously-committing app), then falls back to the last CACHED snapshot with a [STALE] banner, then the PTY grid mirror; log_get requests are NONCE-stamped and the daemon echoes the nonce in the reply HEADER (before "lines" — never scan line text), or a reply buried from an EARLIER request would satisfy a later wait with older data; `appdrive.logGet` returns `LogFetch{json, stale}`), app_click/app_drag/app_type/app_key/app_scroll/app_resize (app_click `mark:true` returns the post-click frame with a crosshair at the click pixel — `src/util/marks.zig`, pure-RGBA red=click/cyan=move markers with step-number labels, drawn via `appdrive.screenshotPngMarked` in surface coords) — **click-and-settle**: whenever a post-input screenshot is requested, the capture waits (bounded, `PostInputWait` in mcp.zig + `appdrive.waitChangeSince`/`FrameRef`) for a frame committed strictly AFTER the input and the caption states 'repainted Nms after the input' vs 'NO repaint within Nms' — a dead click is structurally distinct from a not-yet-landed frame (the old idle-only wait frequently captured the PRE-click frame); an app EXIT during any of these waits is reported as such with the signal + exit summary, never as a failed screenshot — the wait primitives bail on exit but return plain bools, so call sites re-check `app.exited`, and a vanished window pumps briefly (`windowGone`+`settleExit`) because teardown races ahead of the `.exit` frame; `settle_ms`/`wait_change`/`min_change_pct`/`timeout_ms` on all five input tools, `screenshot:true` on key/type/drag/scroll too; app_click's marked screenshot is the DEFAULT reply (mark:false opts out) and captures settle 250ms by default (first post-input frames are often mid-repaint); on continuously-animating apps the dead/live verdict needs `min_change_pct` — the schemas say so; **input fidelity**: app_click holds the button `hold_ms` between press and release (default 100ms, human-like — edge-polling apps collapse a 0ms click into one sample; `appdrive.clickEx` pumps frames during the hold, and server-synthesized template/OCR clicks share the default via `clickTuned`), `count:2/3` = real double/triple click (~80ms apart), `retry:N` re-clicks on a WAITED no-repaint verdict only; app_key `hold_ms` (`appdrive.pressKeyHold`) drives client-side key-repeat; **env-tunable timing defaults** (`Tuning` in mcp.zig, loaded at startup from `SKETERM_MCP_HOLD_MS`/`SKETERM_MCP_SETTLE_MS`/`SKETERM_MCP_TIMEOUT_MS`/`SKETERM_MCP_CLICK_RETRY`, clamped): the static TOOLS_JSON carries `%..._DEF%` tokens rendered per tools/list from the SAME struct the handlers read (`renderedToolsJson`) so description and behavior cannot drift, overrides render as "PROJECT OVERRIDE via <env>, built-in N" and surface in `capabilities` (`input_tuning`); `min_change_pct` is deliberately NOT env-tunable (it decides the verdict, not a timing bound); a `region:{x,y,w,h}` on the input tools / app_wait / app_actions wait steps scopes the change percentages to that rect ("did THIS viewport repaint"), and on screenshot_app the crop region also scopes stats_only/wait_change/stable_ms/burst diffing (`pctDiffRegion` in appdrive.zig — an out-of-bounds rect diffs as 0, never a false "changed"), **app_mouse_move** (button-free pointer motion; x/y absolute or dx/dy RELATIVE — appdrive tracks the injected position per app, the compositor brain derives `relative_motion` from successive absolute motions, so pointer-locked/SDL apps like DOSBox move by exactly the delta; a huge negative delta corner-slams their internal cursor for calibration), **app_actions** (ordered server-side step batch: move/move_rel/click/drag/key/type/scroll/wait (ms)/wait_idle/wait_change/screenshot, per-step report, stops early on app exit, screenshots returned inline — collapses click-wait-screenshot round-trips into one call; per-step `mark:true` accumulates labelled crosshairs drawn onto the NEXT screenshot, leftover marks auto-flush as a final image), app_clipboard_get/set, app_a11y_tree, app_record_start/stop (`fps` caps the capture rate), app_wait (`change_pct` = VISUAL quiescence via `waitVisualSettle` pixel-diffing — settles when frames change less than the threshold, for games that never stop committing), list_installed_apps, close_app. **Framebuffer-app helpers** (games/custom UIs with no a11y tree): app_read_text/app_wait_text = OCR with per-word surface-coord click centers (`src/util/ocr.zig`, libtesseract dlopen'd at runtime like the Opus probe — never an ELF dep; missing lib = one described error; small fonts auto-upscaled pre-recognition), app_template_save/app_templates + app_find_image/app_wait_image = named persistent pixel templates matched by the pure-Zig coarse-to-fine SAD matcher (`src/util/template.zig`; needle alpha<128 = ignored, so transparent-background sprites match; wait-then-click is the coordinate-free primitive), app_macro_save/app_macro_run/app_macros = replayable input macros: every successful injected input is journaled per app (`Journal` in mcp.zig), `last_steps:N` snapshots the tail with think-time gaps as waits, replay goes through `runActionSteps` (the extracted app_actions engine — appTool is split around it into appTool/appToolTail); action steps wait_image/click_image/wait_text make batches state-driven. Assets persist in `$XDG_STATE_HOME/sketerm/{templates,macros}` (`src/ipc/mcpassets.zig`), shared across instances deliberately. run_command/wait_idle detect output quiescence by polling `screen-info`'s `seq` (= `Terminal.activity_seq`) — the GUI dispatch stays synchronous. Dispatch takes an injectable `Backend` so it unit-tests with a scripted fake. Responses must stay newline-free (NDJSON framing); inline images (`imageResult`/`imagesResult`) are base64 PNG content blocks. **Flood safety:** appdrive's `drain()` is time-boxed (100ms), and the daemon stops streaming `.events` to a client whose wbuf exceeds 8MB, resyncing it with a fresh snapshot once it drains (`Client.needs_resync`) — a PTY-spamming app can neither wedge the single-threaded MCP loop nor balloon the daemon. The SAME model covers app pixel frames: native channel units toward an "mcp"-kind client stop entirely past `NATIVE_BACKLOG` (a `native_gap` frame marks the pause; the cap is re-checked AFTER each queued unit run — a burst batch can cross it in one call), and once the client fully drains, `replayNativeChannels` rebuilds its replicas from the LIVE pool mirrors, closed by `native_sync` — appdrive rebuilds the replica IN PLACE on the repeated `chan_open` (window ids stay stable; windows not re-announced are pruned at sync) and `drainLive()` (used at appTool entry + before post-input baselines) pumps to the live head including that pending resync. This is the fix for screenshots lagging whole screens on busy apps (SDL games) — frames incremented while the 100ms drain never caught up to a boundless stale queue; do not reintroduce always-stream toward MCP clients. The mcp cap is deliberately LOW (`MCP_NATIVE_BACKLOG` 1MB, vs 8MB for GUI viewers): an MCP client consumes at replica-compose speed (a full-window memcpy per intermediate frame), so queued bytes map directly onto catch-up latency at the next tool call. **Broker-mode gotcha:** the policy keys on `Client.kind`, and `sketerm mcp` isolation runs the daemon in BROKER mode — the attach kind must travel in the 'A' worker-handoff datagram (`[proto][video][kind]`) or the worker sees `.unknown` and the whole policy silently never engages (this exact bug shipped once: monolith smokes were green while the real MCP stack stayed stale — `smoke-backlog.zig` therefore runs in BOTH smoke-mux and smoke-broker). Commits whose pixel copy was skipped entirely (no viewer with room) accumulate damage in `Native.skipped` and the next shipped commit covers the union — a recovering viewer is never left with stale regions the app won't re-damage. **No-hang invariant:** every appdrive/termdrive connection runs its fd NON-BLOCKING with deadline recvs (`recvExpectFor`/`recvFrameFor`/`fillAvailable`) and a bounded sendFrame (EAGAIN + `write_timeout_ms` poll); `helloProbe` and the term/app handshakes are deadline-bounded too, and `RealBackend.talk` sets a GLib socket timeout — a wedged daemon or GUI costs one bounded, described error, never a hung tool call (plain blocking `recvFrame`/`recvExpect` must NOT be reintroduced on MCP paths). On top of the per-path deadlines, a CENTRAL `Watchdog` thread covers every tool call: past a hard cap (150s, `SKETERM_MCP_HARD_TIMEOUT_MS` overrides, min 30s) it `shutdown()`s the app/term conn fds snapshotted at call start, which makes every bounded loop error out — the call returns, the server keeps serving, affected sessions read as exited. `Conn.fillAvailable` is byte-budgeted (4MB/call — a peer streaming faster than the client consumes kept the fd readable forever, starving the caller-side deadline), and screenshot `zoom` clamps its upscale to 64MP. "App exited" is a NORMAL state handled centrally in `appTool` (`needsLiveApp`): interaction tools return the exit summary immediately; `close_app` is idempotent.

**MCP app observability (freshness, events, honest verdicts).** Three whole classes of wrong conclusion came from tools that could not distinguish "I do not know" from "no". They are now structurally distinct:
- **Frame numbers are the freshness currency.** `Window.frames` (the commit counter) rides on `App.Shot.frame`, so EVERY screenshot caption states `frame N`; every input tool reports the frame it acted at (`PostInputWait.frame_at_input` → `frameNote`), and `screenshot_app min_frame:N` blocks on `App.waitFrameAfter` and ERRORS rather than return an image that is not strictly newer. `wait_change` is relative to the caller's last screenshot and can never express "newer than the input I just sent" — do not present it as if it could. app_click computes its note ONCE after the retry loop, anchored to the FIRST attempt's frame (a later retry's number would accept pixels the earlier presses already produced).
- **`app_wait_log` + `app_log` `pattern`.** `src/util/pattern.zig` is a small documented regex SUBSET (literals, `.`, classes, `* + ?`, `^ $`, top-level `|`; no groups, so `(`/`)` are literal). `app_log` with a pattern reports "0 of N scanned lines match" and shows NOTHING — never the unfiltered tail, which reads as matched content to anyone diffing output. `app_wait_log` scans the whole ring first (an already-printed line matches at once), then follows forward by `from_id`, and hands back the current frame number so the caller can chain `min_frame`. For sub-second visual events the right primitive is still the `OSC 5522` marker (it works for ANY launched app, not only under `term_run`).
- **Verdicts say which of the three states they mean.** `app_wait` reports the frame delta it observed with every outcome, grew `min_frames` (liveness by commit count — the only meaningful wait for an app that never quiesces), and reports never-settling as `ALIVE AND ANIMATING`, a normal state, not a timeout. `appSelect` separates "no sessions exist" / "no app has id N" / AMBIGUOUS-and-here-is-the-roster, because the old single "unknown app" message reads exactly like a crash. `a11yTreeIsBare` (registry with no widgets under it) makes "this app publishes no accessible tree, ever" distinct from "you asked too early" — the tool preamble steers toward `app_perform_action`, so an SDL game must be told that path does not exist for it.
- **Debug wrappers.** `applyDebugWrap`'s gdb line passes SIGPIPE/SIG32-34/SIGCHLD through (`handle ... nostop noprint pass`) — batch mode stops at the FIRST signal, runs the reporting commands against that harmless stop and quits, which is why a threaded app's real fault used to surface in roughly one run in five — and reports `thread apply all bt full` + `info threads`, since the faulting thread is usually not the selected one. The wrapper survives the fault and exits 0, so `appSummary` marks `exit_status_is_wrapper` + `exit_status_note` whenever a debugger signal is inferred: `exit_status` alone must never read as a clean exit.
- **Sampling is not observation (`app_watch`).** A screenshot answers "what is on screen now"; nothing answered "did anything happen in the next N seconds", and for an action whose latency you have not measured those are different questions. The field failure was a menu row reported as broken after two investigations: the action had a ~5.7s pre-roll and then a 6s clip, so every capture landed before or after it while the neighbouring rows' 30-90s clips were on screen at any sampling point. `app_watch` samples continuously (`App.watchChanges` in appdrive.zig) and returns a change TIMELINE — `t=5714ms changed 94.2% (frame 468)` — plus inline thumbnails of the first few change points, encoded AFTER the run from stashed pixels so the encode never perturbs the sampling. Zero changes while the window kept committing frames is a MEASUREMENT ("it is painting, the content did not change"); zero frames is a hung app, and the two verdicts must stay distinct. `app_record_start/stop` is not a substitute — an agent cannot watch a video.
- **Interactive regions are discoverable empirically (`app_hover_map`).** With no a11y tree, finding clickable things is coordinate guessing (the field case: a long sequence of failed clicks on LCARS buttons before the exit turned out to be a door drawn as background art). The sweep moves the pointer over a `cols x rows` grid and reports which cells repaint, as an ASCII map plus surface-coordinate centres. Two refusals are load-bearing: an app that repaints BY ITSELF is detected with three pointer-still control samples up front and refused rather than answered with a map of noise, and an empty map says explicitly that "draws no hover feedback" is not "nothing here is clickable". Nothing is clicked; the pointer is restored to where it was.
- **A hang is diagnosable now (`app_backtrace`).** A crash lands a full report in `app_log`; a freeze used to give nothing, because Yama's `ptrace_scope=1` only lets an ANCESTOR trace and the app's ancestor is the daemon, not the caller — `gdb -p` from the calling session returns EPERM. Both halves live in the daemon: `appdrive` spawns with `SpawnReq.debuggable`, and `app_debug`/`app_debug_data` run gdb daemon-side (see `src/mux/CLAUDE.md`). The app is STOPPED for the duration and resumed, so the reply says so — timings across the call mean nothing.
- **Falling short of `min_frames` is usually arithmetic.** `shortFramesVerdict` in mcp_app.zig: an app painting at 12fps cannot deliver 1400 frames in 115s, and calling that "NOT LIVE / it is not painting (frozen…)" was a false alarm frequent enough to train callers into ignoring the message — the worst reflex, since the identical sentence is how a real freeze announces itself. Only ZERO frames makes a liveness claim; anything else states the observed rate and the arithmetic.
- **"Dead click" and "dead app" are different sentences.** `PostInputWait` records the window's last commit time BEFORE the input (`quietBeforeMs`), so a dry wait on a window that had already been silent for `APP_QUIET_HANG_MS` reports an APP LIVENESS WARNING pointing at `app_backtrace` instead of leading with "it may have hit a dead area". In the field that ambiguity buried the first evidence of a hang — the app had stopped painting before the click that got blamed for it. app_click also stops auto-retrying in that state: more presses only burn the timeout and bury the verdict.
- **Misc invariants.** `close_app` waits for the daemon's kill ACK (`App.killAndWait`) and says so when it does not arrive; `pty.signalTree` signals the child's process GROUP, so wrapper scripts and forked workers cannot be orphaned. Every app-side wait clamps to `mcp.WAIT_CAP_MS` (120s, under the 150s watchdog) and the schemas state it. `include_log_delta` on the input tools reports log lines since the previous input (first call sets the baseline only). `macroNudge` points at app_macro_save once 12 inputs are journalled. `regionOf` accepts `[x,y,w,h]` as well as `{x,y,w,h}`. A test parses the whole of `TOOLS_JSON` — a mis-nested brace in one schema breaks tools/list for every tool and is otherwise invisible until a client refuses to load.

**MCP terminal completion.** `term_run` defaults to output-idle waiting for compatibility; neither it nor `term_wait_idle` implies foreground-process exit. `wait_for:"command"` snapshots the mirrored Screen's OSC 133 completed-zone identity before sending and waits for a new `D`, falling back only to the daemon's real shell-process exit status. Unsupported shells return `command_sent:false` without execution or a fabricated status (a fresh terminal gets a bounded wait for the first prompt mark before that verdict), and a foreground command started OUTSIDE command mode (open OSC 133 C) also refuses the send — its `D` would be misattributed. A timeout retains the token; `term_wait_command` continues the same wait, and both command-mode and idle-mode `term_run` are rejected until it resolves (an interleaved command's `D` would be misattributed; an already-completed token auto-clears). Snapshot v4 carries the OSC 133 state as a TAIL block and restore still accepts v3 — durable sessions on a pre-upgrade daemon must stay attachable. This path is confined to `termdrive` and must not be coupled to `appdrive` or GUI app tools.

**MCP remote ops (SSH sessions, transfers, forwards).** `term_open host:` = persistent SSH session. The transport is picked transparently (`transport` option: auto|mux|ssh, default auto): when the remote host answers `ssh host sketerm-mux --proxy` (key auth + binary in remote PATH — a scp'd `mux-portable` counts), the session is spawned on the REMOTE host's own daemon (`termdrive.Term.spawnRemoteMux`; the bootstrap script rides the spawn argv — nothing typed, no /tmp staging file; `ttl_secs` 3600 bounds orphans) and SURVIVES connection drops: on transport loss without an `.exit` frame, termdrive does a one-shot bounded reattach (`connectSshOnce` + attach + snapshot resync, re-armed per successful recovery) — a dead host costs one bounded attempt, not one per drain. Mux terms are not auto-recorded (the cast would land on the remote host) and `term_list` marks them `"transport":"sketerm-mux","host":...`. Otherwise it falls back to plain interactive `ssh -tt` + ServerAlive keepalives (auth prompts land on the screen). SSH SHELL sessions get OSC 133 integration auto-bootstrapped into the remote shell (`termdrive.buildSshBootstrap`: quote-free outer command any login shell parses → base64 → self-deleting `sh` script that cases on `$SHELL` — bash via `--rcfile` with login-profile-chain emulation, zsh via temp ZDOTDIR carrying the shipped shim, anything else plainly with no integration; needs remote `base64`, like term_exec), so `term_run wait_for:"command"` works on stock remotes; `integration:false` opts out, an explicit remote command skips it, unsupported remote shells degrade to the honest not-ready refusal. The zsh shim emits the FIRST prompt's A mark itself at load (`$precmd_functions` is expanded once per cycle, so hooks registered during the first precmd would otherwise skip that prompt — command mode on a fresh zsh term would sit at prompt_marks_len 0 forever). Idle-mode honesty: `term_run` (idle) sent while integration shows an open command zone appends a queued-as-stdin note instead of letting a quiet screen read as executed, and `term_wait_idle` distinguishes "idle at shell prompt" from "idle, but a foreground command is still RUNNING". `term_open` ALWAYS reports the session's shell: local terms from spawn-time resolution; ssh bootstraps print a visible `[sketerm] remote shell: <name> (...)` line that term_open waits for (bounded, bailing early behind auth prompts) and `termdrive.scanShellAnnounce` parses — a "no integration" announce flips `Term.integration` off so command mode refuses instantly as `unsupported`; `term_list` carries `shell`/`integration` fields. Tool steering: `term_run` is documented as typing INTO the live session shell (its dialect, state persists — cd/export/aliases) and is the PREFERRED path for ordinary commands on integrated terminals (readable on screen/history, exact exit status); `term_exec` is the isolation/dialect-proof/noninteractive/output_file tool — its base64 transport line on screen is the visible cost of asking for isolation, paid only when wanted. `term_exec` runs one command in a LIVE interactive shell with sentinel markers → structured `{completed, exit_status, output}`: the DEFAULT transport base64-encodes the script into a fresh `sh` (dialect-independent — works typed into fish/zsh/bash local or over SSH; the command travels INSIDE the script via a quoted heredoc into a second temp file and runs as `<shell> /tmp/.sk_<nonce>.c`, so it never appears on any process command line — ps/pgrep stay clean — and since it's a child process, `exit` cannot eat the end marker and an interactive `set -e` cannot kill the session), `shell:"bash"` swaps the command-file interpreter for bash-only semantics (pipefail) while keeping isolation (name validated — no metacharacters), `subshell:false` types the POSIX construction directly so cd/export persist (POSIX shells only). A non-completing exec returns `pending` + tracker id + the LIVE screen tail + `alt_screen`/`output_idle_ms`/`interactive_prompt`, and returns EARLY (idle >= 2.5s behind a prompt-looking tail or an alt-screen UI) instead of burning the timeout — answer via term_send_text, then `term_exec_wait` (always reattachable, incl. after client-side aborts) picks up the completion; term_exec refuses to resend meanwhile. All term wait timeouts clamp to 120s (under the 150s watchdog) so one blocked call can't starve term_list/term_read. `noninteractive:true` = DEBIAN_FRONTEND/debconf/needrestart env on the command child only; `output_file` = full untruncated output to a local file (tail inline). `term_wait_exit` waits for real process exit (never output idleness). term_list drains every term (stale progress frames were the bug) and reports last_line; term_read on an exited term carries an exit banner. `upload_file`/`download_file` = scp → SHA-256 verify → atomic `mv` (mismatch = discarded; no host = pure-Zig local copy, same guarantees); the staged temp name preserves the extension (x.service → x.sketerm-part.service) and `verify_command` runs a remote check against the staged file before the move (nonzero = discarded, destination untouched); remote transfer scripts travel base64→sh so the remote login shell's dialect never matters. `port_forward_*` = structured `ssh -N -L` resources: free-port auto-pick, TCP-connect readiness proof before replying, `port_forward_check` respawns a dead ssh on the SAME local port (reconnect counter). `capabilities` preflights OCR/browser/ssh/mode (+ the recordings dir), and reports `headless_gui` (what launch_app actually depends on) with explicit hints on it, `gui_socket` and non-shared modes — a bare `gui_socket:false` once read as "no GUI apps possible" and sent an assistant back to Xvfb; keep those hints. `new_tab` with no GUI socket falls back to opening a headless term. **Every headless terminal the MCP server spawns (term_open, new_tab fallback, transfer/forward helpers) is AUTO-RECORDED as an asciicast v2 .cast** via the daemon's `rec_start` frame (fire-and-forget; finalized with the session, fflushed per event so replayable live): into the `--log` session folder when logging is on, else `$XDG_STATE_HOME/sketerm/mcp-casts/<stamp>-<pid>/` (`term-<id>.cast` / `aux-<n>-<label>.cast`; paths surface in term_open/term_list). `--no-record` disables. All of these are isolated-mode only (they ride termdrive). `app_actions` wait_idle/wait_change steps take `required:true` → timeout fails the batch. launch_app auto-injects `--ozone-platform=wayland` for Chromium-family argv commands and always exports `ELECTRON_OZONE_PLATFORM_HINT=wayland`.

**MCP browser automation (CDP).** `src/ipc/cdp.zig`: hand-rolled DevTools client — libc TCP, RFC 6455 CLIENT WebSocket (masked frames), JSON calls; every op deadline-bounded (no-hang invariant applies). Gotcha: Chromium's DevTools HTTP server IGNORES `Connection: close` — responses must be terminated by Content-Length or the read waits forever. `browser_open` launches a Chromium-family binary (PATH-discovered, `findBrowserBinary`) headless under the Wayland session with `--remote-debugging-port=0` + a user-data-dir (named `profile` = persistent under state dir), reads the real port from the app-log ring (`parseDevtoolsPort`), attaches the newest page target, and registers a `BrowserSession` keyed by app id (`browser_state`); bEval reattaches transparently when navigation replaces the target. Tools: browser_info/navigate/read/elements/click/fill/wait/scroll/eval/form_state/choose/network — clicks and typing are TRUSTED input via `Input.dispatchMouseEvent`/`Input.insertText` at viewport CSS coords; browser_wait timeouts are errors, never silent success; browser_fill reads the field back (password = count only; a submit that detached the field or replaced the target reports field-detached/navigation_started instead of a bogus empty value). **Shadow DOM is first-class:** every element script shares `JS_HELPERS` (`deepQuery` walks open shadow roots, `labelText` climbs to hosts + shadow labels, `activeDeep` drills nested activeElement) — browser_fill's `text_label` finds the input INSIDE a `pl-input`-style host, browser_elements reports role/label/value/checked/options for custom hosts, `browser_form_state` is a one-call form inventory (custom-host + inner control merged, password values as counts, validationMessage), and `browser_choose` picks options in native selects AND custom/ARIA dropdowns (trusted click open → shadow-piercing poll for `[role=option]` → click, with a shadow trigger-button preference). Navigation honesty: browser_click reports `navigated`/`navigation_pending` (ready != complete is never silently final; `wait_navigation:true` blocks until load ends), browser_wait grew `url_exact`/`url_path`/`url_regex` (url_contains substring false-positives) and `network_idle`. **Network capture** (`Network.*` events → bounded 300-entry ring in `cdp.Client`, enabled at browser_open, re-enabled on reattach, events digested during calls + explicit `pump()`): `browser_network` lists method/url/status/type/failure/redirect chain (`redirected_from` keeps the pre-redirect URL findable) with request-body FIELD NAMES only (`extractPostKeys` — values never stored). Browser apps stay normal apps (screenshot/app_key/close_app work; close_app drops the CDP session). Screenshot captions append live page url+title via `browserPageSuffix` (bounded 1.5s, skipped when disconnected). `--force-renderer-accessibility` is always passed. Local daemon only (the CDP port is daemon-host loopback).

**MCP isolation (default).** `sketerm mcp` runs its app tools against a PRIVATE daemon instance (`$XDG_RUNTIME_DIR/sketerm/mcp-tmp-<pid>/mux.sock`, torn down on exit incl. SIGTERM; orphans from a SIGKILL are swept at the next mcp startup). `--durable` / `--name <n>` = named persistent instance (`mcp-<n>/`) — the daemon and its apps survive MCP restarts, and a reconnecting `sketerm mcp --name <n>` auto-reattaches to the still-running app sessions (`App.attachExisting` + `listAppSessions` in appdrive.zig; `App.detach` frees client state without killing the session). `--shared` opts into the user's real per-user daemon + running GUI (the only mode where terminal tools auto-discover the GUI socket; isolated mode requires an explicit `--socket`). Plumbing: `Conn.connectLocalAutostartAt(alloc, sock)` spawns `sketerm-mux --broker --socket <path>`; the daemon derives all aux paths (Wayland hub, a11y dirs) from the socket's directory, so an instance is fully contained in its dir.

**Forwarded-app input encoding.** `src/ipc/evkeys.zig` = char/chord→evdev encoder; `src/ipc/xkblayout.zig` parses the session's compiled-xkb keymap (`src/wlhost/keymaps.zig`: us/gb/fr/be/de) so MCP typing matches the session keymap (spawn `kb_layout`, config `app_keyboard_layout`). The compositor's `keymap` field must match whoever drives the seat.

**AT-SPI accessibility (`app_a11y_tree`).** Daemon-side so it works wherever the app runs. `src/mux/a11yhub.zig` spawns a PRIVATE `dbus-daemon` + `at-spi2-registryd` per app session (private `XDG_RUNTIME_DIR` so the a11y bus is per-session), sets `GTK_A11Y=atspi` (NOT `=1`) + `org.a11y.Status.IsEnabled` BEFORE the app starts (toolkits don't retry a11y registration — ordering is load-bearing, `Hub.setup` blocks on a readiness poll), then walks the tree with a pure-Zig D-Bus client (`src/mux/dbus.zig`, no libdbus, musl-clean — SASL EXTERNAL wants the uid as DECIMAL hex-encoded byte-by-byte). Wire: `app_a11y`/`app_a11y_tree` frames. `SKETERM_NO_A11Y=1` disables. Distinct from `src/a11y/` which is TUI-grid a11y for sketerm's own panes.

`zig build smoke-e2e` uses this to drive a real GUI instance end-to-end. For manual testing: `SKETERM_APP_ID=dev.sker.sketerm.test ./zig-out/bin/sketerm --no-save &`, then `./zig-out/bin/sketerm cli --socket /run/user/$(id -u)/sketerm/<pid>.sock ...`.
