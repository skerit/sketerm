# Mux (durable sessions)

`sketerm-mux` is a single-threaded poll-loop daemon owning one PTY + Parser + authoritative `Screen` per session. The wire protocol (`src/mux/wire.zig`) carries **parsed events, never re-encoded escape sequences** — append-only FrameType/EventTag bytes, every parser `Event` round-trips losslessly. Attach = sequence-stamped `Screen` snapshot (`src/mux/snapshot.zig`) + live event stream.

Transports, all speaking the same protocol:
- Local: Unix socket at `$XDG_RUNTIME_DIR/sketerm/mux.sock`.
- SSH: `ssh -T -o BatchMode=yes <host> sketerm-mux --proxy` over a socketpair (`src/mux/client.zig connectSsh`). `$SKETERM_SSH` overrides the ssh binary — the test rig fakes a remote host this way.
- UDP: mosh-style. SSH bootstrap runs `--udp-listen`, which announces `SKETERM-UDP <port> <keyhex>` and detaches; everything after runs over ChaCha20-Poly1305-sealed datagrams with a go-back-N stream on top (`src/mux/rudp.zig`, pure state machine with injectable clock — adversarial loss/replay/tamper tests live there). Roaming: peer address updates only from authenticated packets (BOTH sides — the client roams too). Best-effort NAT hole punch rides the bootstrap (`src/mux/punch.zig`): the client pre-binds its socket and sends `SKETERM-PUNCH <port>` on ssh stdin, the remote pre-aims its channel at the `$SSH_CONNECTION` address so its sealed keepalives double as punch probes; old binaries on either end ignore all of it. `zig build smoke-udp` proves the traversal with a wrong-announced-port stage.
- **UDP connection tickets**: a client with a live channel asks the daemon to mint a single-use sibling `--udp-listen` (frames `udp_ticket_req`/`udp_ticket`, `udp_ticket:true` welcome capability — never ask old daemons, their `.err` is misattributable), so a NEW process connects with no ssh bootstrap (`Conn.connectUdpTicket`; GUI brokering in `remotectl.mintUdpTicket`, spawned files get `$SKETERM_UDP_TICKET`). Every failure falls back to the normal transports. In broker mode an ATTACHED client's mint is served by the WORKER via `Daemon.broker_sock` — the shared `smoke_ticket.zig` stage runs in smoke-mux AND smoke-broker for exactly that hop. Gotcha that shipped once: a detached daemon has fds 0-2 closed, and anything its children exec that later `close(0..2)`s must park its sockets above the stdio range first (see `runUdpListen`).

**Two shared primitives the daemon side keeps re-reaching for.** `channel_pump.zig` is the libc-only nonblocking local-fd <-> byte-channel pump behind port forwarding, the SOCKS bridge, the remote web helper and the exported mux-client SDK. `Local.enqueue` is all-or-nothing against `out_limit`: a payload that does not fit returns `error.QueueLimit` and leaves the queue byte-identical, because half a payload is a corrupted stream — the caller applies backpressure, it never drops the tail. Every poll goes through `wait`, which retries EINTR itself and reports a cancel-fd wakeup as `.cancelled`, distinct from `.timeout`/`.failed`; a caller that treats those alike hangs or spins. `fs_boundary.zig` orders streamed file-service snapshots against live deltas. Daemon side, `Server` coalesces mutation NAMES (re-statted after the fact, so a name is a fact and a stale payload impossible) and counts overlapping snapshots rather than stacking them; client side, `Client` buffers delta payloads under a generation stamp minted per `begin`, so a superseded snapshot's final chunk is ignored instead of applied. Both are BOUNDED (128 names / 512 payloads / 1MB) and EVERY overflow, allocation failure included, degrades to `resync` — buffer discarded, consumer re-lists. Keep it that way: a busy directory must cost a re-list, never the daemon's memory.

**Debugger access is a daemon privilege (`app_debug`).** Linux Yama (`ptrace_scope=1`, the distro default) lets only an ANCESTOR trace a process, and a headless app's ancestor is this daemon — so a caller in any other process tree gets EPERM from `gdb -p` and a hung app is undiagnosable, while a crashed one gets a full report for free. Both halves live here. (1) `SpawnReq.debuggable` makes the forked child call `platform.allowAnyPtracer` (`prctl(PR_SET_PTRACER, PR_SET_PTRACER_ANY)`) BEFORE exec — verified to survive `execve`, which is why it cannot be granted to an app that has already hung; appdrive/MCP `launch_app` sets it, interactive panes never do, and a session without it is refused rather than handed a gdb that can only report EPERM. (2) `app_debug` → `app_debug_data` (`src/mux/daemon_debug.zig`) runs the debugger as a daemon SUBPROCESS whose pipe is polled per tick exactly like a file job: an attach costs seconds and doing it inline would stall every other session for that long. Attach-scoped, so in broker mode the worker owning the session serves it. The job is resolved back to its client BY ID (the requester can die while gdb runs), output is capped, and a deadline SIGKILLs the debugger so the reply carries a partial dump rather than nothing. gdb runs `-nx` — the user's `~/.gdbinit` must not change what a tool call returns.

**Wayland app forwarding (proto v2).** The compositor advertises the modern client surface (`compositor.zig globals`): core globals at the CURRENT upstream version wherever the added messages are destructors (wl_compositor 7, wl_shm 2, wl_data_device_manager 4, plus the `wl_fixes` registry-destructor global) or fully implemented (wl_seat 10 — v9's `axis_relative_direction` precedes every axis event on v9+ pointer objects, gated per object exactly like axis_value120; wl_surface 7's `get_release` fires with the buffer release, and get_release without an attach is the spec's no_buffer error), plus primary selection, relative-pointer + pointer-constraints, text-input v3 (host IME → `text_commit` intents), xdg-activation, presentation-time, idle-inhibit, pointer gestures, and WITHIN-app dnd (`start_drag` state machine; the drop transfer is daemon-local via the `dnd_send` unit). Buffers are shm plus opt-in LINEAR-only linux-dmabuf — per session via `SpawnReq.gpu` (`sketerm app --gpu`, MCP `launch_app gpu:true`, launcher right-click "Launch with GPU", config `gpu_apps` list) or daemon-wide via `SKETERM_MUX_DMABUF=1`; either announces the global AND drops the forced `LIBGL_ALWAYS_SOFTWARE` (the daemon mmaps the plane fd, no GPU libraries; drivers that refuse CPU mmap degrade to a logged stale buffer, so the default stays shm-safe). Fractional scaling is REAL: the GUI ships its true monitor scale as a `set_scale` intent (scale×120); the brain answers `wp_fractional_scale` `preferred_scale`, honors `wp_viewport` destinations as the surface's logical size (`toplevel_frame` carries lw/lh), and re-announces all scale channels when the intent lands (apps may connect first). Pointer events are frame-grouped (seat v5+ clients buffer input until `wl_pointer.frame`); every advertised version's obligations are implemented — a client binding above an advertised version gets a logged protocol error. **Advertise the highest version whose obligations are implemented** — a client that binds unconditionally above what we advertise DIES (JBR does this for wl_seat and wl_data_device_manager), so a destructor-only bump is never worth withholding; a protocol we don't honour (fifo, commit-timing, drm-syncobj) is worse advertised than absent, because the client waits instead of falling back. Every request added after state-sync v8 latches `Compositor.used_post_v8_request`, which raises `Session.native_state_min` to 9 so pre-v9 replicas (whose tables lack the request) stop receiving the channel instead of dying — and BINDING a bumped global above the old tables' cap (seat 9+, compositor 7, shm 2, ddm 4, any wl_fixes) latches it too, because `bindGlobal`'s version check is not lenient and the bind alone kills an old replica. Keyed on the app's requests, so advertising costs old viewers nothing until an app binds high. **xdg-foreign (v2 only)** is the same story one version later: binding `zxdg_exporter_v2`/`zxdg_importer_v2` latches `used_foreign` and raises `native_state_min` to 10 (a v9 replica has neither interface in its tables, so the bind alone kills it) — and since GTK4 binds them unconditionally, every forwarded GTK4 app now needs a v10 viewer. Handles are 16 bytes of `getentropy` as hex and resolve against a registry shared by every connection of the SESSION (`Session.foreign`), because one `Compositor` serves exactly one connection; revoking a handle queues `zxdg_imported_v2.destroyed` on a brain nobody is about to feed, which is what `Daemon.foreign_flush_pending` + `flushPendingBrains` exist for. **Cross-connection parenting is daemon-authoritative.** A replica re-parsing `export_toplevel` mints its OWN handle, so the handle the app then imports never resolves there — the brain resolves it and ships the answer as a `foreign_parent` pipe unit (child sid, parent CONNECTION id, parent sid), daemon-injected like `toplevel_icon` and replayed on reattach from `Native.foreign_parents`. The connection id IS `Channel.id`, which is the same number the viewer knows the channel by, so `(conn, surface)` is a session-wide window identity needing no new id space; the GUI resolves it through `Terminal` (every app channel of a session rides one mux connection) into a sibling `AppHost`'s GtkWindow. `Surface.tl_parent` stays reserved for `xdg_toplevel.set_parent`; ALL foreign relations, same-connection included, go through `View.toplevel_foreign_parent`. An old viewer skips the unknown unit tag and simply gets no cross-connection parenting. **xdg-dialog (`xdg_wm_dialog_v1`)** is the only modality request in xdg-shell and GTK4 binds it for every modal dialog; binding it latches `used_dialog` and raises `native_state_min` to 11 (a v10 replica's tables have neither interface), and state-sync v11 carries `Surface.modal` plus the live dialog objects. Byte channels (`chan_open/data/close` wire frames) multiplex generic streams over the mux connection — any transport, so forwarded apps roam with UDP. There is NO waypipe: the daemon IS the session's Wayland display. It listens on a per-session display socket (`setupWaylandHub`), sets the shell's `$WAYLAND_DISPLAY` to it, and parses each app connection itself (`Channel.native` = `wlhost/track.zig` tracker + mmapped shm-pool mirrors), tunneling parsed `wlhost/pipe.zig` units as `wayland_native` channels toward the latest attached proto>=2 client. `SKETERM_MUX_NO_WAYLAND=1` disables forwarding. GUI: `terminal.zig` feeds each `wayland_native` channel into a `wlapp.zig` `AppHost` (the `wlhost` compositor brain) that renders the windows locally — no external compositor bridge. **App view modes** (`app_view = window|tab`, default window): window mode attaches TABLESS (`Window.AppSession`, no pane/tab — like a desktop launcher; a held log tab materializes only on exit-without-window, and "Show in Tab" adopts the live terminal into a real pane via `adoptAppSessionIntoTab` + `Pane.adoptAppHost`); a pane that DOES host an app session shows the log + an "App window open" banner (`Terminal.on_app_window` fires on the FIRST toplevel frame — which is also when `app_window_opened` flips; channel-open alone must NOT count, or single-instance handoffs like pcmanfm take the wrong exit path). Tab mode reparents the primary toplevel's overlay into the pane (fully interactive; the hidden GtkWindow is kept alive childless so window-based paths stay valid); "Pop Out Window"/"Show in Tab" in the Ctrl+right-click host menu switch live. A pane MUST call `detachAppHost()` (unlistPane does) before its widget tree dies — the embedded overlay lives inside it. `Terminal.clearSinks` must null EVERY user_ctx-consuming callback (incl. on_app_view/on_app_window); a missed one = post-fence crash from deferred deinit. **Forwarded-app taskbar icons:** the daemon resolves the app's icon to image BYTES on the app's host (`src/mux/icons.zig`, freedesktop lookup) when it sees `set_app_id`, ships them as a `toplevel_icon` pipe unit (daemon-injected; cached per app_id, replayed on reattach), and the GUI builds a GdkTexture + `gdk_toplevel_set_icon_list` (drives xdg-toplevel-icon on Wayland / _NET_WM_ICON on X11). This is how REMOTE apps get their real icon (Wayland's app_id->local .desktop lookup can't). `gdk-pixbuf` is GUI-only (SVG decode) — keep it out of the mux graph. `sketerm app [-u] <host> <cmd>` (`src/remoteapp.zig`) spawns an app session and hands it to the running GUI to render; it therefore REQUIRES a sketerm window open on this desktop (no GUI → it errors). macOS remotes have no Wayland; they stream pixels instead (`winstream`, kind 3). **Remote audio (kind 4):** the daemon is ALSO the session's PulseAudio server (`mux/pulse.zig`, hand-rolled native protocol v15 — the sink STATE floor; v15 also adds the default channel map to GET_SERVER_INFO and 2+3 extra bools to the create-stream request, all version-gated exactly; SHM refused; `PULSE_SERVER` set per session, `SKETERM_MUX_NO_AUDIO=1` opts out). The v15 sink state is session-wide: `Server.sink_running` is daemon-fed from sibling connections (`sessionAudioRunning`) so pactl's own stream-less connection reads RUNNING during playback. `launch_app audio_path` (SpawnReq.audio_capture) tees every stream's PCM to WAV on the daemon host (`mux/wavcap.zig`, libc-only — mp3/ogg would need encoder libs the mux graph can't have): daemon-side `captureUnits` peels open/pcm/close units in `paReadable`, per-stream files `<base>.wav`/`<base>-N.wav`, finalized (RIFF sizes patched) on stream close or channel teardown; capture forces raw pcm units (Opus is gated off — no decoder daemon-side). PCM units flow only to viewers that sent a `subscribe` unit; streams self-clock ON REAL TIME (read_index advances at the declared byte rate via the daemon poll loop's `pulseTick`, REQUESTs/drain replies paced and FRAME-ALIGNED — an unaligned REQUEST leads libpulse clients into unaligned writes that kill their stream, SDL3 zombifies the whole device; an instant-consume clock made apps that gate logic on playback progress hang or race) until a SUBSCRIBED viewer's `consumed` report flips them to viewer-clocked — the GUI's `audio_sink.zig` (async libpulse on the GLib loop, Linux GUI-only dep) reports real playback as the clock; on viewer detach streams revert to the self clock (`has_viewer` counts only subscribed viewers; appdrive deliberately never subscribes). MCP `launch_app audio:"none"` (SpawnReq.no_audio) skips the session's hub AND unsets any inherited PULSE_SERVER (`Pty.spawn clear_pulse_server`) so clients fall back to their own dummy drivers. Playback only; no capture. `-Daudio-opus` (default off, vcodec-style) compresses PCM ~12x: negotiated via subscribe flags, latched per stream, s16/48kHz-family only (44.1k stays raw), `pcm_opus` units carry a raw-byte count so non-decoding consumers keep the clock.

**Current DMABUF policy (supersedes the LINEAR-only note above):** native Linux builds runtime-load EGL/GLES for modifier-backed ARGB/XRGB import; LINEAR keeps the mmap fast path. One importer/context is shared by all app channels in an isolated session worker, and its non-external modifier capabilities are unioned with the guaranteed LINEAR tuples. Legacy monolith mode deliberately stays LINEAR-only because it may fork another PTY after a vendor EGL driver has started threads. The daemon snapshots every committed buffer into a tight BGRA synthetic pool before `wl_buffer.release`, so transport/replay never reread released producer storage. **linux-dmabuf v4 feedback** is spoken whenever a main DRM device resolves (`src/mux/drmdev.zig` picks the first readable+writable `/dev/dri/renderD*`; `SKETERM_MUX_DRM_DEVICE` overrides) — mpv/mesa bind v4 and learn formats ONLY through feedback objects, so a v3-only announcement makes every GPU video output refuse to initialize. No device or an empty format table = the announcement stays at v3 and a v4 bind is a protocol error. `format_table` carries an fd the brain cannot emit, so it rides the `dmabuf_feedback` pipe unit and the daemon materializes the anon fd (same trick as `wl_keyboard.keymap`). Pre-v8 replicas have no feedback interface, so `Session.native_state_min` (6 legacy / 7 modifiers / 8 feedback) gates the native channel, keyed on the app binding dmabuf at v4 or creating a feedback object (`Compositor.used_dmabuf_feedback` — pre-v8 tables cap the global at 3, so the bind alone is fatal there) — advertising v4 must not exclude old viewers until an app binds it. State-sync v7 rides mux protocol 6; v8 adds no fields and is purely that capability signal. `-Ddmabuf-import=false` disables the EGL path; `mux-portable` pins it off. Never hard-link EGL/GLES/libdrm into `sketerm-mux`.

**Current Opus policy (supersedes the older default-off note above):** normal builds compile runtime Opus probing ON by default and load `libopus` with `dlopen`, so both GUI and daemon advertise Opus only when the running host actually provides it; `sketerm-mux` keeps no ELF `libopus` dependency. `-Daudio-opus=false` is an explicit opt-out and `mux-portable` pins it off. Missing libopus, unsupported formats/rates, mixed deployments, and WAV capture fall back to raw PCM. Do not turn the probe back into a hard link: the daemon dependency invariant and runtime negotiation are both load-bearing.

GUI side: `Terminal.initRemote` has no PTY/worker — the socket is watched via `g_unix_fd_add`, EVENTS apply directly, SNAPSHOT swaps `terminal.screen` wholesale and re-wires the sink. `writeRaw`/`requestResize` abstract PTY-vs-socket; **nothing in `src/ui` touches `terminal.pty`**. Remote terminals have `child_pid = -1`; `Pty.reap`/`Pty.closeAndReap` guard on `child_pid <= 0` — do not remove, or the exit poller calls `waitpid(-1)` and reaps arbitrary GUI children. Host strings: `null` = local, `"user@box"` = SSH, `"udp:box"` = UDP.

**Current external-display lifecycle (supersedes the older create-only details below).** `sketerm-mux display run [--size WxH] -- COMMAND...` is the xvfb-run-shaped path (`sketerm run ...` in the GUI binary is sugar for it, inserting the `--` itself — `display.runCommandStart`): generated name, native Wayland environment applied without shell evaluation, command exit status and signal forwarding, then guarded display-only teardown. `create` also accepts an omitted/generated name and `--size`; create/list/inspect replies carry the effective output geometry and GPU policy. `Compositor.output_width/output_height` drive wl_output mode, scale-adjusted xdg-output logical size, and configure_bounds. TTL occupancy includes live external Wayland channels as well as mux viewers, so it starts only after a renderer disconnects. `display_v2` gates custom geometry and `require_display` kills against old daemons that would silently ignore those JSON fields. See `docs/display.md`.

**Rootless Xwayland for external displays.** Display create/run auto-enable X11 when both `Xwayland` and `xwayland-satellite` are in PATH; `--xwayland` requires it and `--no-xwayland` disables it. `src/mux/xwayland.zig` stays libc-only and owns collision-safe `/tmp/.X*-lock` allocation, filesystem + Linux abstract listeners, a mode-0600 MIT-MAGIC-COOKIE-1 authority record, satellite's process group and restart-on-pending-client lifecycle. Satellite is the rootless XWM and turns X windows into ordinary xdg-shell surfaces; do not add an XCB/XWM path to the daemon. Its host Wayland channel is marked `Channel.auxiliary`: frames/input still flow normally, but infrastructure must not keep display TTL occupied. `DISPLAY`/`XAUTHORITY` cross spawn/list plus broker `WorkerReady`/`WorkerMeta`, and the display CLI performs an authenticated X11 setup handshake before reporting readiness. TCP is disabled, teardown kills the exact process group and removes only owned lock/socket/auth files. The real-xterm stage in `smoke_display.zig` runs in BOTH smoke-mux and smoke-broker.

**External display sessions + the controller lease.** `sketerm-mux display create --name <n> [--isolated] [--gpu] [--ttl SECS] --json` (`src/mux/display.zig`) makes a named app session whose child is a KEEPER (`src/mux/keep.zig`, `--keep`: blocks on its PTY) — so an OUTSIDE process renders into the session's Wayland hub and a human attaches the normal GUI later. `create --json` returns `{session, environment:{WAYLAND_DISPLAY, XDG_RUNTIME_DIR, PULSE_SERVER, LIBGL_ALWAYS_SOFTWARE}}`; **callers must never derive `wl-w<pid>` paths** (naming differs monolith vs broker). `inspect`/`list`/`destroy` complete the set; `SpawnReq.ttl_secs` kills a session after N seconds with no attached viewer (counted from creation if never attached). The keeper is spawned as the DAEMON'S OWN binary (`/proc/self/exe --keep`) because a client can't know the daemon host's binary path — so **any process hosting a `Daemon` must answer `--keep`** (the smoke rigs do; without it the keeper re-runs the smoke recursively). Spawn `.ok` and session `list` carry `wl_display`/`pulse_server`/`runtime_dir`; in broker mode those ride the worker's `'Y'` ready datagram, now `Y{json}` (`WorkerReady`, bare-int still parsed). **Controller lease:** all viewers SEE a forwarded app, one drives it. First non-read-only attach takes a free lease; `control_req` (acquire/release/takeover) and `control_state` (broadcast to every attached client, `controller` = "do YOU hold it") are the wire surface. Enforcement is `isSeatIntent` in `nativeClientData` — non-controller input units are DROPPED, but data-transfer replies (clip_send/clip_data/primary_data/drop_data) and selection offers/`set_scale` are NOT gated (they answer the daemon or describe the viewer). Controller death/detach hands the lease to the oldest eligible viewer by `Client.id` (the clients list is `swapRemove`d — its order is not age). `mux attach` grew `--read-only`/`--control`; appdrive attaches with `control:true`, its log side-connection and one-shot CLI attaches read-only. Covered by `src/smoke_display.zig` in BOTH smoke-mux and smoke-broker.

**Cast playback sessions** (`SpawnReq.cast_path`; frames `play_control`=30 / `play_state`=94; welcome capability `cast_playback:true`). `Session.source` is a union — `.pty` or `.cast` — and **nothing may assume `.pty`**: go through `ptyPtr()`/`masterFd()`/`childPid()`, which degrade to null/-1 for casts. A cast session has NO child process, keeper, PTY, shell integration or Wayland/audio/a11y hubs; client `.input` is dropped, client `.resize` is ignored (the recording's dimensions win), and `rec_start` is refused. Playback is timer-driven (`castTick`, the pulseTick shape) and output bytes flow through the SAME ingestion path PTY reads use — `ingestBegin`/`ingestBytes`/`ingestFinish` in daemon.zig, extracted from `drainSession`; never grow a second byte→events path. A cast is UNTRUSTED input: `EventCollector.untrusted` drops kitty `t=f`/`t=t`/`t=s` APCs BEFORE they reach `kitty_inline.rewrite` or `grid/kitty_images.zig` (both open — and for `t=t` DELETE — daemon-host paths named by the file); Screen responses discard via the source-aware `sinkWritePty`. EOF keeps the session ALIVE with its final screen (`state:"finished"`, never `sessionExited`); seek resets parser + Screen and silently replays from file start in bounded chunks across ticks, ending in one SNAPSHOT. Catch-up batches are bounded but output events are never dropped — when behind, process a batch and re-tick immediately.

User entry points: `sketerm ssh [-u] <host>`, `sketerm mux [host] [list|attach <name>|new|kill <name>]`, bare `sketerm mux` = TUI picker, "New Durable Tab" in the palette.

**Stale daemons self-upgrade when idle.** The welcome announces `build` (git describe, in ALL binaries' build_options); `Conn.upgradeStaleIdle` probes sessions (`.list`) + running jobs (`job_list`) over long-standing verbs and uses the ancient `.shutdown` frame — so even pre-announce daemons get replaced. Runs at GUI startup (`main.upgradeLocalDaemon`, BEFORE the window spawns its own pane session — from inside a running GUI the daemon is never idle) and in the browser's remote connect worker. A BUSY daemon is never bounced (its sessions are the user's work); the browser status line reports it serving an older build. This is why "the fix didn't work on <host>": a 2-day-old daemon serves 2-day-old code to every new client until something restarts it.

**Session identity and durable-job namespace compatibility.** Every lifetime gets a random 128-bit lowercase-hex `origin_id`; `origin_name` is the immutable spawn name. A session answers to its current mutable name AND to `origin_name` (a child that captured `$SKETERM_SESSION` before a rename can still attach) and to nothing else — there is deliberately no alias history, because an unbounded set of names one session routes under is a hazard, not a feature. The ID crosses monolith spawn, broker worker handoff, worker-ready validation, list/session metadata, panel-only attach, and `SKETERM_SESSION_ORIGIN_ID`. An attach may carry that ID as a lifetime fence; both monolith and broker refuse a matching name whose current ID differs, and every reconnect attach requires it. `attach_identity` advertises the additive identity-first GUI handshake: a panel-capable GUI requests `identity_first`, receives `session_meta` before the initial snapshot, and passes that identity into Terminal construction; clients that do not request it retain snapshot-first ordering. **The broker is the rename authority**: it renames its own record and sends the worker one `R` with the new name; a worker forwards an attached client's request as `N` and answers that client from the broker's `n` result. No two-phase transaction, no alias cap, no kill-on-missing-ack — the broker's record is what routes, so a worker that misses the `R` only shows a stale display name. Broker/worker control datagrams are plain `sendmsg`; the one whose loss a client can see is the `A` client-fd handoff, and that failure is reported to the client instead of dropping the descriptor. A newly forked worker must close every inherited broker descriptor, or its duplicate can suppress client EOF. The listener exports a physical canonical absolute socket path, resolving symlinked existing parents while preserving a nonexistent leaf. Fs-job journals use its hash; startup still adopts the pre-state-dir socket-sibling namespace and nothing else (a journal is cheap to lose and impossible to half-migrate if the rename is the only commit).

**Panel routing is one compatible presenter per session attachment, no binding.** The daemon delivers a panel request for session S to the earliest still-attached GUI whose negotiated `panel_rpc` is at least the panel-only requester's required version. A v1 requester therefore keeps working through a v2 daemon with v1 or v2 presenters, while a v2 requester never reaches a v1 presenter. There is deliberately no requester-to-presenter binding and no stickiness: when a presenter detaches or dies, the next request simply selects whichever compatible attachment is present then, so a GUI restart is picked up by the very next call with no invalidate dance. No compatible attachment at all fails the route pre-delivery with `no_compatible_gui` (resend-safe). The GUI registry keys relayed panels by the immutable session `origin_id` alone, not a Terminal pointer: duplicate viewers share panels, one viewer's reconnect/close cannot close the scope, and permanent last-viewer teardown does. GUIs that never negotiated panel_rpc remain terminal viewers but are not compatible presenters.
