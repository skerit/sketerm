# File browser (`sketerm files`)

UI in `src/ui/browser/` (BrowserView per pane, `BTab` tabs on a GtkNotebook), pure helpers in `src/filebrowser/`. **The GUI never touches the disk**: every file op (list/trash/delete/copy jobs) goes to the daemon via `sendOp`/`startDaemonJob` — so env-isolation in tests must isolate the DAEMON's env too (trash resolves against the daemon's `$HOME`, not the GUI's).

**Listings stream.** The daemon stats entries in time-boxed batches from a tick pump (`pumpFsListings`, never inside the fs_op callback — one slow NFS dir must not stall the poll loop) and ships them as the `fs_reply more:true` chunk run; the GUI renders every chunk as it lands and commits a navigation on the FIRST one. Child counts ("N items") are deliberately NOT in listings — they follow as upsert deltas on the open view. Don't reintroduce synchronous whole-directory work into `handleFsOp`. **close_view aborts an in-flight listing** (terminator reply with `aborted:true`; every closeViewOf call site cancels its pending FIRST, so the terminator never lands on a live accumulator) — statting on for a dead view queues bytes AHEAD of the client's next request, which is dead-UI on slow links. GUI side: socket-driven renders go through `scheduleListingRender` (120ms leading-edge throttle, render.zig), count deltas take the `Dir.countOnlyIndex` fast path (in-place write + `colview.refreshEntryRow` single-row resplice — `children` is never a sort input) instead of the full-model rebuild, and remote thumbnails fetch `REMOTE_THUMB_CONCURRENCY`-wide (pool in `BrowserView.remote_thumbs`, queue purged on navigation). **renderList splices a WINDOW, not the whole store**: unchanged rows (identity = path/depth/zebra-parity, minus `BTab.changed_paths`) keep their exact GObjects so GTK never rebinds them — that is what makes a delta storm hover-stable; content mutations outside the delta path MUST call `tab.noteChangedFull` (mediacols.applyToDir change-detects for meta) or their rows show stale cells, and reused rows get their nulled `dir`/`entry` pointers re-aimed by `rebindReused` (skip that and interactions crash). **Navigation commits INSTANTLY** (`navigateMode` calls `commitNavigation` with the empty streaming candidate at click time; `p.navigation` nulled so pending ownership is already the tab's; a refused listing lands as `setLoadError` on the visible dir). Icons view still full-rebuilds. Remote thumbnails also persist their transport sidecar bytes locally (`$XDG_CACHE_HOME/sketerm/remote-thumbs/`, md5(host:path) + mtime header, lazy oldest-first sweep — preview.zig "local persistent cache" section): a revisit decodes from disk with zero remote traffic. Local hosts must never land there (their daemon cache is this disk). **Thumbnail cache format is split by host kind**: the LOCAL daemon installs spec freedesktop PNGs (shared with the desktop's other file managers/pickers — keep it), while remote requests send `wire_cache:true` and the remote daemon caches the codec bytes themselves (`~/.cache/sketerm/thumbs/<md5>.jxl|webp` for 128px thumbs, `thumbs/xl/` for 512px previews — both tiers, no PNG anywhere; freshness = file mtime equals the source's, freedesktop-PNG read-through on miss, media metadata still computed per fetch) and serves that file with `keep:true` — consumers must not unlink a kept asset, and `FsJob.done_kept` keeps daemon job-reaping from unlinking it either (fsjob.zig `runWireThumb`). A full renderList per delta is the storm that ate clicks and flickered hover for minutes on big remote folders — don't reintroduce it.

**Retry identity is two-tier: `client_token` rotates per attempt, `transfer_token` (the ledger intent token) is stable for the logical transfer.** Every cross_copy submission carries both; a daemon that finds a FAILED job with the same transfer_token RESTARTS it from its journal under the same job id — same `.skpart`s, same `.sketerm-copy-*` destination stage, same quarantine/phase — instead of minting a fresh job whose randomized stage orphans the old data (the bug that left 6 GB `.sketerm-copy-47`/`-50` twins behind). ALL no_replace cross copies stage (not just moves), so an interrupted no-replace tree copy resumes instead of colliding with its own partial root. Fs-job journals live under `$XDG_STATE_HOME/sketerm/fsjobs/<sock-hash>/` (reboot-durable; `Daemon.fsJobsDirAlloc` is the one path rule — it canonicalizes the socket path itself, so every spelling of one listener maps to one journal dir, and smoke_fs uses it too), NOT the runtime dir. A move that fails after the `copied` phase reports "the copy is complete and installed; …" and its retry redoes only source cleanup. The cross-copy helper pipelines a bounded read/write window (`CrossCopy.transferBytes`) and caches verified digests per run (`hashCached`, stat-identity keyed) — do not reintroduce stop-and-wait chunking or per-phase full re-hashes of unchanged files.

**The transfers UI is two-tier** (`jobpanel.zig`): an ambient one-line strip (ring + sentence + percent/rate/ETA; click, its Details button, or Ctrl+Shift+J toggles tier 2) and the Transfer Center (cards: name-first head, custom byte bar with the RESUMED prefix shaded dimmer, "resumed at N" chip, current-file line, area sparkline; right-click copies full endpoint paths). Cards sort by their meter's first-seen order — state changes must never reshuffle the list under the cursor. Progress seeds from a job journal apply ONLY when the byte copy is skipped (`resume_phase > 0` in fsjob) — seeding a re-copying restart once SUMMED a dead attempt's counter with the fresh run. A re-paste of endpoints an older non-running intent holds ADOPTS that intent in the ledger (same token → the daemon restarts the old job, staged data included) and retires other stale duplicates as superseded — that adoption is what killed the "two identical Copy N items rows" class; don't reintroduce fresh-mint-per-paste. A restarted no_replace job may claim an existing destination ONLY with a journaled prior attempt and full shape+hash proof; a fresh job never claims (the collision smoke pins this for moves).

**Transfers are daemon-owned cross_copy jobs, never the GUI's.** Same-host copy = a job on that host's daemon; cross-host picks a COORDINATOR (`jobs.pickCoordinator`): remote-to-remote prefers the DESTINATION host's daemon, whose `--job` helper dials the source itself — the bytes never route through the client machine. That needs the `cross_move` welcome capability (delete_src + dial_tries honored, dial failures stamped `kind:"unreachable"`), and moves/no-replace copies additionally need `durable_copy_v2` (journaled staging, cancellation election, restart adoption) — against an older daemon such jobs DEFER with a "restart the daemon" message rather than run with weaker semantics; host strings on the wire are COORDINATOR-relative ("" = its own disk, the peer resolved through ITS ssh/UDP config). An unreachable peer costs one fast capped-dial failure and `fallbackDirectCopy` resubmits through the local daemon as the next bounded automatic attempt (same staged `.skpart`; a still-connecting local conn rides the retry timer). Cross-host MOVES are `delete_src` on the cross_copy spec — journaled, or a daemon-restart respawn silently degrades the move to a copy; the delete runs strictly after the verified rename (a failed delete retries with a cheap hash-skip re-verify). The client-mediated fstransfer path remains only for download-to-open, edit sync-back, and the no-capable-daemon fallback. **Failure kinds drive retries**: every `fs_reply` error carries `kind` — only `"transport"`/`"unreachable"` earn AUTOMATIC retries (3 attempts, 5s apart, one shared budget across daemon and mediated routes); `"permanent"` (ACCES, NOENT, NOSPC, ...) fails immediately, and manual Retry on a failed row is NEVER gated on the kind. A dropped link during a running attempt is first resumed IN-HELPER (`reconnect`, exact byte offset, per-drop backoff, generous job-wide budget) — only exhaustion charges a transport attempt. The daemon's cancellation-election lock is nonblocking in the poll loop (`tryRequestCancel`); helpers may block on it, the daemon never does.

State lives in three places: `places.json` (state dir; bookmarks+labels, recent, saved queries, section order/hidden, widget sections, sidebar px — user-global, last save wins), `viewmem.json` (per-folder view/sort/columns memory), and `config.conf` (`files_*` keys = defaults for new tabs). Don't add a fourth.

Gotchas that bite:
- `renderPlaces` destroys and rebuilds EVERY sidebar row on any change. A row/menu handler must copy its ctx string to a stack buffer BEFORE calling anything that re-renders (savePlaces/navigate/toggle) — the ctx dies mid-handler otherwise. Same pattern throughout `places.zig`.
- Context menus are `classicmenu.zig` (hand-built popover rows, NOT GMenuModel — model menus can't do per-item icons). Submenus only off the TOP menu (depth limit); per-item heap ctxs register with `root.own(cb, ctx)`; the popover pops down BEFORE the handler runs. `itemIconEnabled` builds a row insensitive rather than hiding it.
- The per-TAB menu is NOT the browser's own: `ui/tabhost.zig` owns the close/duplicate/new-window rows for both inner-tab consumers and asks `tabs.tabMenuSpec()`'s predicates at popup time. Add a browser-only row in `tabs.menuExtra`, never a second gesture on the label box.
- `classicmenu` short menus disable vertical scrollbar negotiation after measuring; an unused `GTK_POLICY_AUTOMATIC` scrollbar changes height during popup realization under desktop themes. Longer menus keep automatic scrolling.
- Browser keyboard chords live in `nav.browser_chords`; an audit test cross-checks them against `input.default_bindings` — a chord shadowing a global action must declare `.shadows` or the suite fails.
- Danger verbs (trash/delete) act on the whole selection when the clicked row is in it (`ops.menuTargets`, same rule as copy) — keep new verbs consistent.
- Column widths: `colview.applyExpandPolicy` — auto Name expands, explicit Name = NO expander (surplus stays blank, Nemo-style); `fittedNameWidth` clamps to the viewport so splits never grow a horizontal scrollbar.
- **Version-control badges never run git in the GUI.** Local AND remote roots submit the daemon's `git_status` job (`gitstat.zig`); all parsing, precedence, rollup and badge decisions live in `filebrowser/gitstatus.zig` so both test roots cover them -- and the DAEMON scans with the same `gitstatus.Scanner`, so producer and consumer cannot drift. The verb runs `git status --porcelain=v2 --branch --ignored -z` and emits per record `path` + `text` (the pre-v2 collapsed character, still the only field an old client reads) + `xy` (both columns) + `orig` (rename source) + `kind:"submodule"`, then one `repo` event with the branch header. **`--ignored` is unconditional**: its default `traditional` mode collapses a wholly ignored directory into ONE record, so a 50k-file build tree costs one line. Caps are 4096 change records, 8192 total, ignored emitted in a SECOND pass so truncation loses ignored first. **The `repo` event is what tells a clean repository from a non-repo**: `repo:false` (and no event yet) = no version-control phrase at all; `repo:true` + an empty overlay = a clean repository. A result landing must `noteChangedFull` the rows it touches or the windowed splice keeps stale chips. Changes DEEPER than the watched views raise no delta, so `gitstat.ensurePoll` re-polls a repo root on a timer paced at 40x the last job's cost (20s floor, 5min ceiling) and only while the window is active.
- `BrowserView.ownerWindow()` is the route to `Window`/`Config` (browser code must not cache Window pointers).
- Informational windows such as Preferences and About are separate, transient, non-modal toplevels (`AdwPreferencesWindow` / `AdwAboutWindow`), never attached `AdwDialog` sheets.
